# i18n — `provideBillyI18n` / `BillyI18nService`

Built-in strings of the billy-layout components (button labels, dialog copy,
tooltips, empty states, password criteria, file-viewer controls…). **English is
the default; French ships with the library.** Any string can be overridden, and
the label inputs of the components (`labelSave`, `backLabel`, …) always take
precedence over the dictionary.

## Setup

```ts
// app.config.ts
import { provideBillyI18n } from 'billy-layout';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBillyI18n('fr'),
    // …
  ],
};
```

With per-string overrides (any subset of the dictionary):

```ts
provideBillyI18n('fr', {
  saveBar: { save: 'Enregistrer' },
  deleteDialog: { confirm: 'Oui, supprimer' },
});
```

## Runtime switching

The service is signal-based: changing the locale re-renders every label
instantly — no reload.

```ts
private readonly i18n = inject(BillyI18nService);

switchToFrench(): void {
  this.i18n.setLocale('fr');
}
```

| Member | Description |
|---|---|
| `locale` | `Signal<'en' \| 'fr'>` — active locale (default `'en'`). |
| `strings` | `Signal<BillyI18nStrings>` — resolved dictionary (locale + overrides). |
| `use(locale, overrides?)` | Sets locale and replaces overrides (what `provideBillyI18n` calls). |
| `setLocale(locale)` | Switches locale, keeping current overrides. |

## What it covers

| Group | Component / usage |
|---|---|
| `topbar`, `notifications`, `actionBar` | shell chrome: tooltips, "Sync now", empty category |
| `addButton`, `uploadButton`, `saveBar`, `pageHeader` | default labels (inputs still win) |
| `deleteDialog`, `toastr`, `snackbar` | dialog copy, default toast titles, snackbar texts |
| `checkmark`, `appLoading`, `emptyState` | loader labels, per-type empty-state copy |
| `password`, `dropdown`, `datepicker`, `inputEmails`, `codeDisplay`, `attachments` | form-field strings; `datepicker.dateLocale` drives month/day names |
| `viewer` | file-viewer controls (close, page navigation, zoom) |

## Value-utils diagnostics

`VatUtils.describe`, `IbanUtils` and `EmailUtils` diagnostics accept an
optional locale and are wired to the service inside the code fields — with
`provideBillyI18n('fr')` the field messages ("Valid number", country names…)
are French end-to-end:

```ts
VatUtils.describe('BE0690614660', 'fr');      // messages in French
VatUtils.countryLabel('BE0690614660', 'fr');  // 'Belgique' via Intl.DisplayNames
```

## Adding a language

The built-in dictionary type is `BillyI18nStrings`. `BillyLocale` is currently
`'en' | 'fr'`; for another language, pass a full override object on top of the
closest base locale:

```ts
provideBillyI18n('en', NL_STRINGS satisfies BillyI18nOverrides);
```

Contributions adding first-class locales are welcome.
